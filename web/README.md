# Как выложить «Финансы» на GitHub Pages

Пять шагов, каждый делается один раз. Дальше обновление приложения — три команды.

Проверить, что всё готово, можно так: открыть адрес приложения с телефона, увидеть
экран «Войти через Google», войти и записать любую трату. Если она появилась на
ноутбуке — переезд удался.

---

## 1. Проект в Firebase

1. [console.firebase.google.com](https://console.firebase.google.com) → **Create a project**.
   Имя любое, например `finance`. Google Analytics можно выключить.
2. **Build → Firestore Database → Create database**. Регион — `eur3` или `europe-west`.
   Режим спрашивают на старте: выбирайте **production mode**, правила зададим на шаге 3.
3. **Build → Authentication → Get started → Sign-in method → Google → Enable**.
   Support email — ваша почта. Save.
4. **Authentication → Settings → Authorized domains → Add domain**: добавить
   `<ваш-логин>.github.io`. Без этого вход с боевого адреса будет отклонён.
5. **Project settings (шестерёнка) → General → Your apps → Web (`</>`)**.
   Имя любое, хостинг Firebase подключать **не надо**. Скопировать объект
   `firebaseConfig` — он понадобится на шаге 2.

Тариф остаётся бесплатным (Spark): на двоих человек с несколькими сотнями записей
в месяц лимиты не расходуются заметно, карта не требуется.

## 2. Свой config.js

```bash
cp web/config.example.js web/config.js
```

Подставить в `web/config.js` значения из `firebaseConfig` и вписать свою почту
в `FINANCE_ALLOWED_EMAILS`.

Ключи Firebase для веба не секретны: они лежат в открытом виде на любой странице,
которая с Firebase работает, и сами по себе ничего не открывают. Доступ к данным
закрывают вход через Google и правила из следующего шага.

## 3. Правила доступа

Открыть `web/firestore.rules`, заменить почту в списке на свою (если она другая),
скопировать содержимое файла в **Firestore Database → Rules** и нажать **Publish**.

Это единственное, что закрывает данные. Без этого шага любой, кто узнает адрес
приложения, сможет прочитать и стереть весь учёт.

## 4. Репозиторий на GitHub

Создать пустой репозиторий (без README и .gitignore) на
[github.com/new](https://github.com/new) — имя, например, `finance`.
Бесплатный GitHub Pages работает только из публичного репозитория: код будет виден
всем, данные — нет, они в Firebase за правилами из шага 3.

```bash
git remote add origin https://github.com/<ваш-логин>/finance.git
git branch -M main
git push -u origin main
```

## 5. Включить Pages

**Settings → Pages → Build and deployment**:
- Source: **Deploy from a branch**
- Branch: **main**, папка **/docs** → Save.

Через минуту приложение будет по адресу `https://<ваш-логин>.github.io/finance/`.

На телефоне: открыть этот адрес в Chrome → меню → **Установить приложение**
(в Safari — «Поделиться» → «На экран "Домой"»). Появится иконка ₸, приложение
запускается без адресной строки и открывается без сети.

---

## Обновить приложение после правок

```bash
node dev/build.js && node tests/smoke.js
node dev/build-web.js
git add -A && git commit -m "что изменилось" && git push
```

`docs/` — это готовая страница, она лежит в репозитории целиком: Pages ничего не
собирает на своей стороне. Поэтому `node dev/build-web.js` после правки
`index.html` обязателен, иначе на сайте останется старая версия.

Новая версия подхватывается при следующем открытии приложения (страница берётся
из сети, кэш — только запасной вариант на случай оффлайна).

## Если что-то не работает

| Что видно | В чём дело |
|---|---|
| «Не заполнен файл config.js» | не сделан шаг 2 или после него не запущен `node dev/build-web.js` |
| После входа пусто, в шапке красный ₸ | не опубликованы правила (шаг 3) или почта в них не совпадает с той, под которой вошли |
| Вход открывается и сразу закрывается | домен `<логин>.github.io` не добавлен в Authorized domains (шаг 1.4) |
| «У аккаунта … нет доступа» | вошли не той почтой; нажмите «Войти другим аккаунтом» |
| На сайте старая версия | не запущен `node dev/build-web.js` перед коммитом |
