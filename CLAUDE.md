# Финансы — приложение учёта финансов A Catering

Одностраничное веб-приложение на чистом JS без сборщика. Живёт на **Firebase Hosting**
(`https://finance-anuar.web.app`) как PWA — ставится на телефон. Данные там же, в
**Firestore** проекта `finance-anuar`, вход через Google, поэтому телефон и ноутбук
видят одно и то же. Раньше жило артефактом Claude — тот адрес продолжает работать,
см. «Как выкатывать изменения».

Язык интерфейса — русский, валюта — тенге (₸). Пользуются вдвоём.

## Главное правило: формат файла

`index.html` — **это тело страницы, а не полный HTML-документ**. В обёртку
`<!doctype html><html><head>…</head><body>…</body></html>` его укладывают снаружи:
на сайте это `dev/build-web.js`, в артефакте — сам Claude, в тестах — `dev/build.js`.

Поэтому в `index.html` **не должно быть** тегов `<!DOCTYPE>`, `<html>`, `<head>`, `<body>`.
Файл начинается прямо с `<title>Финансы</title>` и дальше `<style>`, разметка, `<script>`.

Если добавить эти теги — страница сломается.

Ограничения, которые сохраняем, чтобы файл работал и в артефакте тоже:
- внешние стили только с `fonts.googleapis.com` (уже подключены Unbounded / Onest / JetBrains Mono);
- весь CSS и JS — инлайн, одним файлом;
- `localStorage` работает, но только для мелочей: имя «Я: …», выбранная тема и очередь
  неотправленных записей; всё остальное — в облачной базе. Читать и писать его только
  внутри `try/catch`: в приватном окне он бросает исключение.

## Как запускать локально

Прямое открытие `index.html` в браузере не сработает: нет `window.claude` (облачной базы)
и нет обёртки документа. Для локальной разработки есть заглушка базы в памяти:

```bash
node dev/build.js      # соберёт dev/test.html из index.html + dev/shim.js
# затем открыть dev/test.html в браузере
```

`dev/shim.js` подделывает `window.claude.use("db")` — Firestore-подобный API поверх
объекта в памяти. Данные живут до перезагрузки страницы, этого хватает для проверки логики.
Заглушка вшивается в `dev/test.html` целиком, а не подключается ссылкой, — иначе страница
не работает по `file://` и в предпросмотре, где внешние скрипты не грузятся.

Обрыв связи имитируется из консоли: `window.__failAdd = "entries"` заставляет заглушку
отклонять добавление в эту коллекцию (так проверяется очередь), `null` возвращает как было.

Автотесты (Playwright, сценарии кликами):

```bash
npm i -D playwright        # если ещё не стоит
node tests/smoke.js        # проходит по всем вкладкам и печатает состояние
```

Если браузеры Playwright не скачаны (`npx playwright install chromium` не прошёл),
тест сам запустится на установленных в системе Chrome или Edge.

## Как выкатывать изменения

Основная площадка — **Firebase Hosting** в проекте `finance-anuar`. Порядок:

1. отредактировать `index.html`;
2. `npm test` — сборка тестовой страницы и прогон сценариев, ошибок быть не должно;
3. `npm run deploy` — пересоберёт `docs/`, выложит сайт и опубликует правила из
   `web/firestore.rules`;
4. закоммитить и `git push origin main` — репозиторий anuarbekyt/Finance-Anuar
   держим в синхроне с тем, что выложено.

`docs/` — готовая страница целиком, а не исходник, и она коммитится. Выкладка мимо
`node dev/build-web.js` оставит на сайте старую версию — поэтому `npm run deploy`
собирает сам. Требует однократного `npx firebase login` (браузерный вход, делает
только владелец аккаунта).

Первичная настройка описана в [web/README.md](web/README.md). `docs/` годится и для
GitHub Pages (папка `/docs` в публичном репозитории), если понадобится второй адрес.

Артефакт (`https://claude.ai/code/artifact/f7c1e768-ebfa-4fad-a6b8-a543b3d1c619`) остался
как запасной вариант и продолжает работать: `index.html` не знает, где он запущен.
Если понадобится опубликовать туда, это инструмент `Artifact`, тот же URL (иначе
создастся новый артефакт с пустой базой), и из новой сессии артефакт сначала надо
прочитать (`action: "read"`), иначе публикация будет отклонена.

## Веб-сборка

`index.html` берёт базу из `window.claude.use("db")`. В артефакте этот объект даёт
Claude, на обычном хостинге — `web/firebase-adapter.js`: он поднимает Firestore
(его API совпадает с тем, что приложение уже использует) и закрывает страницу
экраном входа через Google, пока вход не пройден. Логика приложения о хостинге
не знает и знать не должна — все различия живут в `web/`.

| Файл | Зачем |
|---|---|
| `dev/build-web.js` | собирает `docs/`: документ целиком, манифест, service worker, иконки |
| `web/firebase-adapter.js` | `window.claude.use("db")` → Firestore, вход через Google, `window.financeAuth` |
| `web/config.example.js` | образец `web/config.js` — настройки Firebase и список допущенных почт |
| `web/firestore.rules` | правила доступа; **единственное**, что закрывает данные |
| `firebase.json` / `.firebaserc` | что выкладывать (`docs/`) и куда (проект `finance-anuar`) |
| `dev/make-icons.js` | перерисовывает иконки приложения в `web/` (запускать редко) |
| `web/README.md` | пошаговая настройка Firebase Hosting, входа и установки на телефон |

Ключи Firebase в `docs/config.js` публичны по устройству самого Firebase и ничего
не защищают — прятать их бессмысленно, защищают правила. А вот список почт менять
надо в двух местах сразу: в `web/config.js` (понятное «нет доступа») и в
`web/firestore.rules` (собственно запрет).

Сообщения об ошибках хранилища в `index.html` не должны упоминать Claude или
артефакт: один и тот же файл работает на обоих площадках.

## Структура index.html

Один файл, порядок сверху вниз:

1. `<title>` и `<style>` — токены дизайна, затем компоненты: карточки, плитки, строки,
   модалки, чипы месяцев, календарь, план.
2. Разметка: шапка → верхняя лента вкладок → восемь `<section class="panel">` по числу
   вкладок → нижняя навигация `#bottomNav` (вне `.wrap`, она `position:fixed`).
   Плиток табло в разметке нет — только пустой `#dashTiles`, содержимое рисует
   `renderTiles` из `TILE_DEFS`; над ним `#dashRange` (чипы периода) и кнопка «Плитки».
3. `<script>` — вся логика в одной IIFE со `"use strict"`.

Секции скрипта помечены комментариями `/* ============ ИМЯ ============ */`:
`CONSTANTS`, `STATE`, `UTIL`, `ТЕМА`, `ОЧЕРЕДЬ НЕОТПРАВЛЕННЫХ ЗАПИСЕЙ`, `MODAL SYSTEM`,
`DB WIRING`, `QUICK ENTRY PARSER`, `TABS`, `SETTINGS`, `RECEIPT HANDLING`, `ENTRY FORM MODAL`,
`RECURRING`, `GOALS`, `COMPUTATIONS`, `RENDER`, `ТАБЛО: ПЕРИОД И ПЛИТКИ`, `QUICK BUTTONS`,
`ПЛАН МЕСЯЦА`, `CALENDAR`, отчёты, история, `INIT`.

Правки делать точечно (Edit по уникальному фрагменту), файл целиком не переписывать.

## Дизайн

Направление — «приборная панель»: графитовая база и три сигнальные лампы.
Янтарь (`--accent`) — внимание и действие, мята (`--good`) — пришло и оплачено,
коралл (`--bad`) — просрочено и минус. Четвёртого сигнала нет намеренно: `--warn`
равен `--accent`, поэтому банеры очереди и предупреждений говорят тем же голосом,
что и кнопки. Добавлять новый цвет — значит ломать эту систему.

- **Тёмная тема — основная.** Она лежит на голом `:root`, светлая — под
  `@media (prefers-color-scheme: light)` и `[data-theme="light"]`. По умолчанию
  `themeMode = "dark"`, круг переключателя: тёмная → светлая → как в системе.
- Шрифты: `--font-display` (Unbounded) — только вывеска, заголовки модалок, месяц
  в календаре и надзаголовки (`.section-label`, `.quick-label`, `.qb-title`);
  `--font-ui` (Onest) — весь текст; `--font-num` (JetBrains Mono) — все суммы, даты
  и таблично выровненные числа. Смешивать роли не надо: цифра всегда в моно.
- `--well` — «утопленная» поверхность: поля ввода, ячейки календаря, чипы месяцев,
  иконки строк. Карточка приподнята (`--card`), табло вдавлено. Третьего уровня нет.
- Плитки `.tiles` — один прибор, а не россыпь карточек: сетка в 1px, разделители
  рисует обводка каждой плитки (`box-shadow: 0 0 0 1px var(--line)`), иначе пустая
  ячейка при нечётном числе плиток осталась бы полосой цвета линии.
- Знак ₸ в шапке (`#cloudDot`) — он же лампа состояния облака: зелёная, когда записи
  уходят в базу, красная, когда нет. Цвет ставит `setCloudStatus`.
- Надзаголовки — прописные, трекинг `.16em`, Unbounded. Текст в них короткий:
  на 390px длинная фраза прописными занимает три строки.
- Чипы периода над табло (`.range-chip`) — тот же язык, что у чипов месяцев: утопленный
  `--well`, выбранный залит янтарём. Кнопка «Плитки» прижата вправо (`margin-left:auto`),
  чтобы не уезжать влево, когда чипы переносят её на свою строку.
- Телефонные привычки, которые нельзя терять при правках стилей:
  `.wrap` добавляет сверху `env(safe-area-inset-top)` (приложение рисуется под строкой
  состояния, иначе вывеска налезает на часы); `body { touch-action: manipulation }`
  снимает зум по двойному касанию, щипок оставлен ради фото чека; поля ввода на `≤759px`
  ровно 16px — на меньшем размере iPhone сам приближает страницу при фокусе.

## Вкладки

Восемь вкладок. На ноутбуке (`≥760px`) все восемь лежат в верхней ленте `#tabbar`.
На телефоне лента скрыта, вместо неё нижняя панель `#bottomNav` на пять кнопок:
Главная, Платежи, План, Календарь и «Ещё». Под «Ещё» (`MORE_TABS`, `openMoreModal`)
живут Долги, Цели, Отчёты и Все записи. Просрочка по долгам показывается бейджем
на «Ещё», иначе на телефоне о ней негде узнать. Кнопки нижней панели — те же
`.tab` с `data-tab`, поэтому `switchTab` подсвечивает обе навигации разом.

| Вкладка | Что делает |
|---|---|
| Главная | быстрая запись голосом/текстом, кнопки частых трат, табло плиток за выбранный период, карточка записей периода, ближайшие платежи, последние записи |
| Долги | кто кому должен, срок возврата, разбивка крупного долга на месяцы с графиком |
| Платежи | постоянные доходы, кредиты со сроком, обязательные платежи, подписки |
| План месяца | остаток на начало, текущий баланс, планируемые доход/расход/остаток, платежи месяца, план по статьям |
| Цели | накопления: срок, где лежат деньги, сколько откладывать, чтобы успеть |
| Календарь | сетка месяца с расходами по дням, список записей за выбранный день |
| Отчёты | месяц, полосы по статьям с раскрытием и редактированием записей, экспорт CSV |
| Все записи | фильтры по типу, месяцу, статье, поиск; итоги по отфильтрованному |

## Модель данных (коллекции облачной базы)

**entries** — все денежные записи:
`type` (`expense` | `income` | `lend` | `owe` | `goal_deposit`), `amount`, `date` (`YYYY-MM-DD`),
`category`, `note`, `person`, `dueDate`, `status` (`open` | `closed`), `termMonths` (рассрочка долга),
`goalId`, `receiptId` (id документа в `receipts`), `addedBy`, `createdAt`, `updatedAt`.
Поле `receipt` (data-URL прямо в записи) — старый формат: он ещё читается, но новые чеки
так не сохраняются, иначе подписка тянет все картинки при любой правке любой записи.

**receipts** — фото чеков, по документу на чек: `data` (data-URL сжатого JPEG), `createdAt`.
Отдельно от записей, читается по требованию (`loadReceipt`), в подписки не входит.

**recurring** — всё регулярное, различается полем `kind`:
- `income` — постоянный доход (зарплата, аренда);
- `credit` — кредит/рассрочка: `termMonths` + `startPeriod` (`YYYY-MM`, месяц первого платежа);
- `bill` — обязательный платёж;
- `subscription` — подписка.

Общие поля: `name`, `amount`, `dueDay`, `cycle` (`monthly` | `yearly`), `dueMonth` (для годовых),
`category` (попадает в разбивку по статьям в отчётах), `active` (`false` — «на паузе»:
платёж выпадает из плана, календаря и напоминаний, но отметки сохраняются; переключается
в его карточке), `startPeriod` (месяц, с которого платёж вообще учитывается — так
сдвигают уже оплаченные подписки вперёд).

**recurringPayments** — отметки «оплачено/получено», id документа = `<recurringId>__<период>`,
период это `YYYY-MM`, а для годовых — `YYYY`. Поля: `recurringId`, `period`, `amount`, `paid`, `paidDate`.

**debtPayments** — график погашения долга, разбитого на месяцы. id = `<entryId>__<YYYY-MM>`.

**goals** — цели накоплений: `name`, `targetAmount`, `deadline`, `depositPeriod`
(`weekly` | `monthly`), `startAmount` (сколько уже лежало до старта), `place` (где лежат деньги).

**categories** — статьи: `name`, `kind` (`expense` | `income`), `budget` (план на месяц, 0 = считать по среднему).
Засеваются дефолтным списком при первом запуске пустой базы.

**quickButtons** — кнопки частых трат: `label`, `icon`, `type`, `category`, `goalId`, `amount`
(0 = спросить сумму), `note`, `order`, `uses` (массив дат `YYYY-MM-DD` нажатий за последние
30 дней — по нему `qbSorted()` поднимает часто используемые кнопки наверх).

**monthPlans** — id документа = период `YYYY-MM`, поле `openingBalance` (остаток на начало месяца).

**uiSettings** — настройки вида, по документу на настройку. Пока один документ `dashTiles`:
`order` (массив id плиток табло) и `hidden` (какие из них спрятаны). Лежит в облаке,
а не в `localStorage`, чтобы телефон и ноутбук показывали табло одинаково.

## Ключевые функции логики

- `addEntry(payload, done)` — единственная точка добавления записи. При обрыве связи
  (или когда `db` вообще нет) запись уходит в очередь `localStorage`, а не теряется;
  `done({id, queued, qid})` даёт материал для «Отменить» через `undoAdd(res, silent)`.
  Все новые места, где создаётся запись, писать только через неё.
- `flushQueue()` — досылает отложенное; вызывается при подключении к облаку, по событию
  `online`, по кнопке «Отправить сейчас» и таймером. Очередь живёт в памяти (`queueList`),
  `localStorage` — только чтобы пережить перезагрузку страницы.
- `splitQuickPhrases(text)` — дробит фразу на несколько записей («такси 1500, обед 3000»).
  Дробит, только если сумма есть в КАЖДОМ куске, иначе «статья развлечение, 12500 — Паб»
  и «долг Ануару 5000, до 10 сентября» развалились бы на бессмыслицу. Разобранная пачка
  показывается в `openBatchModal(items)` — тип, статья и сумма правятся прямо в списке.
- `repeatEntry(e)` — копия записи сегодняшним днём (кнопка «↻» в строке). Долги не копирует.
- `overdueRecurringList()` / `overdueDebtsList()` — просроченное одним правилом: по ним
  и баннер на дашборде, и бейджи на вкладках (`renderTabBadges`). Считать просрочку
  где-то ещё отдельно — значит развести числа.
- `parseQuickEntry(text)` — разбор фразы с диктовки: сумма (цифрами, с пробелами в тысячах,
  словами — «пять тысяч»), срок «до 10 сентября», статья «статья сигареты», направление долга
  («мне должен» / «я должен»). Диктовка на телефоне искажает слова, поэтому разбор нарочно
  терпимый: сначала выдёргивается дата, потом сумма, остальное — имя или заметка.
- `guessCategory(text, kind)` — угадывает статью по словам фразы («такси» → Транспорт),
  чтобы её не выбирать руками после каждой диктовки. Сначала ищет корень имени уже заведённой
  статьи, потом словарь `CAT_HINTS`. Возвращает только существующую статью, новых не выдумывает.
- `findCategory(name, kind)` — поиск статьи без учёта регистра и пробелов. Через неё идут все
  проверки перед созданием статьи, иначе «продукты» заводит дубль к «Продукты».
- `recActiveIn(r, period)` — учитывается ли регулярный платёж в этом месяце (проверяет
  `active`, `startPeriod`, срок кредита, годовой цикл). Через неё фильтруются дашборд,
  план и календарь — новые места фильтровать тоже через неё.
- `paidRecurringIn(period)` — оплаченные регулярные за месяц: `{rec, payment, amount, date}`.
  Единственный правильный способ сложить платежи за месяц: у годовых ключ отметки — год,
  поэтому фильтр `recurringPayments` по `period === "YYYY-MM"` их теряет. Заодно отсекает
  отметки удалённых платежей. Дашборд, отчёты, календарь и CSV считают только через неё.
- `monthPlanSummary(period)` — вся арифметика месяца в одном месте: её считают и вкладка
  «План месяца», и плановые плитки табло. `plan` статьи — это бюджет либо среднее;
  `expected = max(plan, fact)` идёт в прогноз. Подтягивать `plan` под факт нельзя: тогда
  перерасход не виден нигде. Планируемый расход — это платежи и кредиты (`planRecurOut`)
  + статьи (`expectedCats`) + откладывание (`planGoal`) + долги к возврату (`planDebt`);
  считать его где-то ещё своей формулой — значит развести числа между вкладками.
- `debtDueIn(period)` — мои долги, которые надо вернуть в этом месяце: доля рассрочки либо
  весь остаток в месяце срока. Просроченное переносится в текущий месяц. Без этого весь
  остаток по долгам садился бы в каждый месяц подряд.
- `rangeOf(dashRange)` — период табло на Главной (`сегодня` | `неделя` | `месяц` | `квартал` |
  `год` | свой диапазон) → `{from, to, label, months}`. Факт считается по датам, всё плановое —
  по месяцам, которые период задевает: планы, бюджеты и регулярные платежи живут месяцами.
- `dashStats(rg)` — вся арифметика табло; плитки только форматируют её поля.
- `TILE_DEFS` / `tilesCfg()` / `renderTiles(s)` — каталог плиток, сохранённый набор с порядком
  и отрисовка. Новая плитка добавляется записью в `TILE_DEFS` (id, заголовок, `calc`) — она
  сама встанет в конец табло и появится в списке настройки; в HTML плиток нет.
- `debtOpenAmount(e)` — непогашенный остаток долга с учётом отмеченных месяцев рассрочки.
  Итоги по долгам считать только через неё, не по `e.amount`.
- `goalPlan(g)` — сколько осталось накопить и сколько откладывать в неделю/месяц.
- `creditPeriods(r)` / `creditPaidCount(r)` — график кредита и сколько платежей закрыто.
  У кредита `startPeriod` — начало всего графика, поэтому «Сдвинуть →» для него запрещён.
- `catAvg3(cat, period)` — среднее по статье за 3 прошлых месяца (план, если бюджет не задан).
  Делитель — месяцы, что статья существует; месяцы без трат из делителя не выбрасываются.
- `renderAll()` — вызывается на каждый снимок базы, перерисовывает все вкладки; обёрнута
  в try/catch, ошибка показывается баннером вверху страницы.
- `openModal` / `closeModal` — модалки лежат стопкой `modalStack`, закрываются Escape и
  аппаратной кнопкой «назад» (через `history.pushState`). Необратимые действия — через
  `confirmModal(title, text, yesLabel, onYes)`.
- `toast(msg, undoFn)` — если передан `undoFn`, в тосте появляется «Отменить» и он живёт
  5 секунд вместо 2,6. Так отменяются добавленные записи, повтор и удаление быстрой кнопки.
- `accountBlockHtml()` — блок «Аккаунт» в настройках. Рисуется, только если есть
  `window.financeAuth` (его заводит адаптер веб-сборки): в артефакте выхода нет.
- `applyTheme(t)` / `setTheme(t)` — тема `dark` | `light` | `auto`, кнопка 🌗 в шапке.
  Тёмная стоит первой и она же значение по умолчанию: иначе телефон со светлой
  системной темой открывал бы светлый вид. Текущее значение держится в `themeMode`,
  а не читается из `localStorage`: в приватном окне чтение падает, и переключатель
  залипал бы на светлой.
- `openMoreModal()` — лист «Ещё» с разделами из `MORE_TABS`. Пункты помечены
  `data-goto`, переключением занимается общий обработчик, лист только закрывается.
  Новый раздел добавлять в `MORE_TABS`, а не отдельной кнопкой в нижней панели:
  шестая кнопка там не помещается.
- `renderMeChip()` — единственное место, где рисуется чип «кто добавляет»: в шапке
  показана одна буква имени, полное имя — в подсказке.

## Соглашения

- ES5-стиль: `var`, `function`, без стрелок и классов — так писался весь файл, не смешивать.
- Никаких зависимостей и сборки.
- Всё, что видит пользователь, — по-русски; числа через `fmtMoney`, даты через `dateLabel`
  и `monthLabel` (именительный) / `monthLabelGen` (родительный, для фраз «учёт с октября»).
- Любой пользовательский текст в HTML — только через `escapeHtml`.
- Множественное число — через `pluralize(n, "запись", "записи", "записей")`.
- Снимки базы заморожены (`Object.freeze`), поэтому `docsOf()` копирует объект перед
  добавлением `id` — иначе строгий режим бросит исключение и подписка молча умрёт.
- Мобильный экран — основной сценарий (записи диктуются с телефона), проверять на 390px.
- Новых цветов и шрифтов не заводить: три сигнала и три шрифтовые роли описаны
  в разделе «Дизайн», всё остальное собирается из существующих токенов.
